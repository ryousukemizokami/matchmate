## 7.1 パフォーマンス要件

**Supabaseクライアント最適化:**

```typescript
// useSupabaseClient.ts - シングルトンパターン
let supabaseInstance: any = null

export const useSupabaseClient = () => {
  if (!supabaseInstance) {
    const config = useRuntimeConfig()
    supabaseInstance = createClient(config.public.supabaseUrl, config.public.supabaseKey)
  }
  return supabaseInstance
}
```

## 7.2 セキュリティ要件

### 7.2.1 認証

**Supabase Authの活用:**

```mermaid
sequenceDiagram
%%{init: {'theme': 'neutral'}}%%
    participant User as ユーザー
    participant App as アプリ
    participant Auth as Supabase Auth
    participant DB as Database

    User->>App: ログインリクエスト
    App->>Auth: signInWithPassword
    Auth->>Auth: 認証情報検証
    Auth-->>App: JWT Token
    App->>App: セッション保存
    App->>DB: データアクセス（JWT付き）
    DB->>DB: RLSポリシー検証
    DB-->>App: データ返却
```

### 7.2.2 認可（Row Level Security）

**RLS設計方針:**

| テーブル | SELECT | INSERT | UPDATE | DELETE |
|---------|--------|--------|--------|--------|
| users | 自分のみ | - | 自分のみ | - |
| teams | 全員 | 監督のみ | オーナーのみ | オーナーのみ |
| team_members | 関係者 | 選手/監督 | 監督のみ | 監督のみ |
| games | 関係者 | 監督のみ | 監督のみ | 監督のみ |
| attendances | 関係者 | 監督のみ | 選手（自分のstatus）/監督（position情報） | 監督のみ |

### 7.2.3 入力検証

**クライアント側検証:**

| 項目 | 検証内容 |
|------|----------|
| メールアドレス | 形式チェック |
| パスワード | 6文字以上 |
| 必須項目 | 空欄チェック |
| 日付 | 有効な日付形式 |

**サーバー側検証:**
- Supabaseのデータベース制約による検証
- RLSポリシーによる権限チェック

## 7.4 エラーハンドリング

### 7.4.1 エラーの種類と対応

```mermaid
graph TD
%%{init: {'theme': 'neutral'}}%%
    Error[エラー発生]
    Error --> Network[ネットワークエラー]
    Error --> Auth[認証エラー]
    Error --> Validation[バリデーションエラー]
    Error --> Server[サーバーエラー]

    Network --> N_Handle[再試行を促す]
    Auth --> A_Handle[ログイン画面へ誘導]
    Validation --> V_Handle[入力欄にエラー表示]
    Server --> S_Handle[エラーページ表示]
```
